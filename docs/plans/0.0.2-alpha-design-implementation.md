# Provedba FigCraft dizajna u List2Cart 0.0.2-alpha

Status: implementacija pokrenuta. Pripremljen src/ui/contracts.ts i alpha-agent-handoff.md; početni build i 8 frontend testova prolaze. Prvi zahvat: src/ui/shell.ts s pet glavnih odjeljaka, karticama proizvoda i izvornom ikonom. Završna vizualna provjera i integracija modula drugog agenta još slijede.
Referenca: docs/design/list2cart/List2Cart-v2-popravci-2026-11-19.figcraft (60 okvira, 7 cjelina).

## Cilj

Prenijeti odobreni izgled i tokove u stvarnu aplikaciju za desktop i mobitel, uz postojeće podatke, izravnu sinkronizaciju i izvornu ikonu. FigCraft prikazuje primjere stanja: postoci, potvrde, iznosi i prava u aplikaciji moraju dolaziti iz stvarnih podataka. Trenutačna verzija u manifestima već je 0.0.2-alpha.

## 0. Priprema prije paralelnog rada — glavni agent

- Pregledati postojeći diff i razdvojiti zatečene izmjene od novog rada. Ne resetirati, prepisivati ili automatski commitati tuđi rad.
- Provjeriti lokalne upute te zabilježiti početni build i postojeće testove, uključujući eventualne postojeće pogreške.
- Pripremiti zajednički ugovor u src/ui/contracts.ts: podaci potrebni prikazima, tipizirane korisničke akcije, pozivanje renderiranja i otvaranje/zatvaranje dijaloga. Koristiti postojeće domenske tipove; bez dupliciranja poslovne logike.
- Glavni agent ostaje jedini urednik modela, usmjeravanja i povezivanja događaja u src/main.ts. Prikazi drugog agenta primaju podatke i vraćaju akcije preko dogovorenog ugovora.
- Usuglasiti osnovne CSS varijable, prijelomne širine i prefikse klasa. Tek tada počinje paralelan rad.

## 1. Podjela datoteka i odgovornosti

### Glavni agent

Isključivo uređuje:
- src/main.ts — stanje, navigacija, vezivanje događaja, integracija novih prikaza i uklanjanje zamijenjenih prikaza.
- src/styles.css — zajednički izgled, komponente i prilagodba desktopu/mobitelu.
- src/ui/contracts.ts — zajednički ugovor; nakon početka paralelnog rada promjene prvo najaviti drugom agentu.
- src/ui/shell.ts, src/ui/commerce/** — navigacija, popisi, katalog, poslovnice, usporedba cijena, kupnja, provjera računa i povijest računa.
- src/assets/** i src/icons.ts — izvorna ikona i zajedničke ikone.

Odgovoran za glavni raspored, pet glavnih odjeljaka, stvarne iznose/količine, poruke i stanja učitavanja u trgovačkim tokovima. Postojeći CSV uvoz i pretragu trgovaca treba sačuvati pri promjeni izgleda.

### Drugi agent

Isključivo uređuje nove module:
- src/ui/family/** — obitelj, moji uređaji, detalj člana i pregled pristupa.
- src/ui/sync/** — prikaz stvarnih faza po uređaju, čekanje veze, pogreške, potvrda primitka i prikaz sukoba.
- src/ui/pairing/** — poziv, pridruživanje, usporedba koda, čekanje obostrane potvrde i odustajanje.
- src/ui/about/** — O aplikaciji, stvarna verzija i licenca.
- src/ui/family-sync.css — stilovi ovih modula s prefiksom fs-, bez globalnih selektora.
- testove u navedenim novim direktorijima kada provjeravaju stvarno ponašanje.

Ne uređuje main.ts, styles.css, api.ts, types.ts, sync-progress.ts, Rust/Tauri ni manifeste. Dostavlja module i popis potrebnih akcija glavnoga agenta. Ne povezuje prototipska stanja izmišljenim uspjehom ili vremenskim odgodama. Ne prikazuje članova prava kao uređiva ako postojeći API ne podržava njihovu stvarnu promjenu.

### Zajednička granica

API i backend ostaju izvan paralelnog vizualnog zahvata. Ako nedostaje operacija ili događaj, drugi agent navodi točan zahtjev i očekivane podatke. Glavni agent procjenjuje potreban zahvat te ga provodi zasebno, nakon provjere zatečenih izmjena. Svi javni izvozi i CSS pravila prolaze kroz dogovoreni ugovor.

## 2. Redoslijed isporuke

1. Glavni agent: priprema ugovora i zajedničkih komponenti; početni desktop i mobilni okvir.
2. Paralelno: glavni agent radi popise/proizvode/kupnju/račune; drugi agent obitelj/uparivanje/sinkronizaciju/O aplikaciji u svojim direktorijima.
3. Prva integracija: obitelj + O aplikaciji; provjera navigacije i ugovora prije nastavka.
4. Druga integracija: uparivanje i status sinkronizacije vezani na postojeći API i SyncTracker. Drugi agent prijavljuje spremnost modula, a glavni agent jedini mijenja main.ts.
5. Zajednički pregled nedostajućih stanja: datotečni uvoz/izvoz, CSV mapiranje, duplikati, uklanjanje člana, prazni rezultati i pogreške. Postojeće funkcije ne smiju nestati zato što nisu nacrtane.
6. Glavni agent završava integraciju, vizualnu provjeru i pripremu alpha izdanja. GitHub/release nije dio ovog plana bez naknadne upute.

## 3. Pravila protiv sudaranja

- Svaka datoteka ima jednog urednika. Tuđi modul mijenja njegov agent na zahtjev, ne oba istodobno.
- Nema paralelnog formatiranja cijelog projekta, promjena ovisnosti ili masovnog preimenovanja.
- Prije integracije drugi agent dostavlja popis datoteka, izvoze, potrebne akcije i rezultate provjera.
- U dijeljenom radnom direktoriju ne mijenjati grane, resetirati ni raditi git add/commit preko tuđih izmjena. Ako se koriste worktreeovi, najprije osigurati da oba polaze od dogovorenog početnog stanja, a ne samo od HEAD-a koji ne sadrži trenutačni diff.
- Jedan integrator pokreće zajednički build i provjere nakon svake isporuke. Zatečene promjene ostaju očuvane.

## 4. Kriteriji prihvata

- TypeScript/Vite build prolazi; postojeći relevantni testovi prolaze, a početni problemi su odvojeno zabilježeni.
- Vizualna provjera barem na širini 390 px i desktopu; nema vodoravnog preljeva, nedostupnih gumba, rezanog teksta ni sadržaja skrivenog donjom navigacijom/tipkovnicom.
- Popis → kupnja → količina/cijena → provjera razlike → spremljeni račun radi sa stvarnim podacima.
- Pretraga bez barkoda, odabir poslovnice i CSV mapiranje ostaju dostupni.
- Uparivanje provjereno na dva stvarna procesa/uređaja, uključujući pogrešan kod i odustajanje. Ako drugi uređaj nije dostupan, ta se provjera ne proglašava dovršenom.
- Sinkronizacija prikazuje stanje pojedinog uređaja; lokalno spremanje nije potvrda udaljenog primitka. Prekid veze čuva čekajuće promjene.
- Duplikati ostaju sačuvani do izričite odluke. Ne uvoditi spajanje polja ako backend podržava samo odabir aktivnog zapisa i arhiviranje duplikata.
- O aplikaciji prikazuje verziju iz aplikacije i odgovarajuću licencu, uz izvornu ikonu.
- Završno dostaviti snimke glavnih ekrana te popis stvarno provjerenih i preostalih stavki.
